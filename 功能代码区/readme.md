# 图书馆管理系统：修改说明

## 每次修改必须遵守的规则

1. 按原负责人的命名、注释和代码组织方式修改，只调整实现需求所必需的部分。
2. 每次修改代码后，更新本 README 中对应负责人的说明，写清“原来的问题、具体发生情境、这次怎么改”。没有修改的模块不要写成已经修改。
3. 保留已有功能规则。增加图书仍采用：同校区同名书的总数和可借数量各加 1；只有新书才询问类别、价格和总数。
4. 测试使用临时数据，不能把测试借还操作写入正式的 book.txt 和 borrow.txt。

## 当前约定与数据格式

- 最多 300 条图书记录，每条总数量为 1～200 册，可借数量为 0～总数量。
- 借阅记录最多 5000 条，价格为 0～500 元。
- 图书编号区分具体记录；两个校区的同名书分别编号。书名、类别、姓名、学号不含空格；英文和普通符号可以使用。
- 沿用 7 字段图书格式。需要区分版本时，在书名内注明，例如 `数据结构(第2版)`，避免被同校区同名查重合并。暂时没有单独的出版社、版本字段。
- `309-4` 是 C 控制台项目；`LibraryGui` 的 Qt 界面自己读写数据文件，不调用 C 函数，因此涉及相同行为时需要同步修改两边。

book.txt 每行：

```text
编号 书名 类别 价格 总数 可借数量 借阅次数
XL-B001 红楼梦 文学 49.80 100 80 1
```

borrow.txt 每行：

```text
借阅编号 书名 学号 姓名 借书日期 应还日期 未还数量 天数 状态 [图书编号] [实际还清日期]
```

第 10 字段图书编号和第 11 字段实际还清日期都是兼容旧数据的可选字段。新借阅和部分归还记录有图书编号；全部还清后才增加实际还清日期。例如：

```text
L000001 三体 S001 小明 2026-11-01 2026-12-01 2 30 未归还 XL-B001
L000002 三体 S002 小李 2026-10-01 2026-10-31 0 34 已归还 XL-B001 2026-11-04
```

未还数量表示这条记录还欠多少本；“天数”在借书时是 30，归还时更新为从借书到本次归还的天数。新记录的第 6 字段始终是应还日期，第 11 字段才是最后一本实际还清的日期。历史数据没有图书编号、且书名对应多本图书时，不自动猜测归属；没有实际还清日期的旧已还记录继续保留，不能按应还日期猜测清理时间。

**Qt 对接注意：** 此次只改控制台源码，Qt 的读写、提醒和历史清理由正在负责界面的另一位 AI 处理。Qt 需要兼容 9、10、11 字段，并在写回时保留第 11 字段，否则可能丢失实际还清日期；两个程序不要同时运行并修改同一份文件。旧版可执行程序也可能丢失新增字段。

| Qt 读取时直接跳过坏记录，之后保存可能把这些记录从文件中抹掉。 | 遇到错误图书字段、重复编号、无效数量或错误借阅行时提示读取失败，避免在不完整数据上继续保存。 |

### 此前的数据规模调整

- 增加图书的缓存调整为 300 条，达到 300 条后不允许再增加新记录；对已有记录加 1 仍可进行，但每种书总数不能超过 200。
- Qt 的图书总数量上限同步为 200，价格上限同步为 500。

### 2026-11-04：完善借还、提醒和历史记录（控制台）

本次修改 `borrow.c`、`guihuan.c`、`remind.c` 和相关头文件；新增 `loan_data.c` 处理大家共同用到的输入、记录读写和保存保护；`main.c` 增加日期变化时的刷新。编译时要把 `loan_data.c` 一起加入工程。

| 原来的问题和具体情境 | 这次怎么改 |
| --- | --- |
| 输入 `2025-02-30` 这样的日期，原程序只看格式，可能把不存在的日期当成有效日期。 | 检查年月日和闰年；借书、还书日期不能晚于今天，归还日期不能早于该条记录的借书日期。借期固定为借书后 30 个日历日，逾期仍可归还。 |
| 输入 `2abc`、0、负数、过大的数字，或者姓名中有空格，原来可能读错数字或让后面的输入错位。 | 借还时逐行检查数量、姓名、学号和日期；数量必须为正，借书不能超过可借数量，归还不能超过选中记录的未还数量。姓名和学号不允许空格，英文和符号仍可输入。 |
| 借了 3 本只还 1 本时，库存和记录需要分别增加和减少 1；同一个人借了多次，还需要知道还的是哪一笔。 | 以图书编号、姓名和学号匹配未还记录；有多条时让用户选择。部分归还后仍为“未归还”，剩余 2 本继续提醒；全部还清时改为“已归还”。 |
| 原来先保存借阅记录，再单独修改库存；如果第二步失败，就会出现记录已经借出但库存没变。 | 先检查该书的库存和未还记录是否相符，再准备两个临时文件、备份原文件并依次替换；替换失败会尝试恢复，保存中途意外结束时下次启动先恢复。库存本来已与记录不符、旧同名记录无法确定校区时，停止借还并提示核对，不自动猜数据。 |
| 离到期 7 天时需要提醒，逾期后也要每天继续提醒；借还或跨天后，旧提醒可能没有更新。 | 借还成功后和查看提醒时重新生成 `remind.txt`；程序运行期间每秒检查日期变化。应还日期距今天 7 天及以内、包括逾期的未还记录都会提醒，还清后移出提醒。 |
| 11 月 1 日借的书应还 12 月 1 日，但 11 月 4 日已经全部还清；按应还日期清理会把保留时间算错。 | 最后一本还清时记录实际还清日期；按日历日期满 3 天清理，例如 11 月 4 日还清，11 月 7 日开始清理。未还记录即使逾期也不会因为过期被清理。旧已还记录缺少实际还清日期时先保留。 |
| 借阅记录文件损坏或超过 5000 条时，直接覆盖可能丢失其他人的记录。 | 先检查记录格式和数量；发现错误或达到 5000 条上限时拒绝新借阅，不改库存和原记录。 |

**正式数据需要先核对：** 目前 `L000001` 的《红楼梦》没有图书编号，两个校区都存在同名书；它记录未还 25 本，而仙林 `XL-B001` 的总数 100、可借 80，差额是 20 本。不能据此确定该借阅属于哪个校区，也不能自动选 20 或 25；此外，这条旧记录写的借书日期是 2026-11-29、应还日期是 2026-12-06，二者相差 7 天，也需要核对。因此这本书的借还会被拦截，需由团队核实后再整理数据。`XL-B037`《百年孤独》也有 25 本库存差额，现有借阅文件中没有对应未还记录；该书借还同样需要先核对。此次测试没有修改正式 `book.txt` 和 `borrow.txt`。
